## 独立环境的实际请求

复用专用隔离服务 `new-api-ui-batch-5b1`，监听 `127.0.0.1:3332`，使用独立 SQLite 卷和合成钱包/受限令牌/受控上游。重置只发生在此合成测试卷；没有读取或覆盖生产数据。New API 请求继续通过技能脚本 `api.js`，没有使用真实上游或实际付款。

本阶段异步候选运行二进制与当时宿主候选一致：SHA-256 `030fa4de013e984e2c5543161301f0b7166d1769700855a3c9a1581beb3069a6`。Go 构建完成后挂载复用镜像，没有 Docker 镜像构建。此前同步阶段 SHA 与本记录不同，属于先前验证快照。

| 实际案例 | 入口 | 预扣 → 最终额度 |
| --- | --- | ---: |
| 返回图片但不报告 usage，固定 USD 0.025 | `/async/v1/generateImage` | 12,500 → 12,500 |
| 图片缓存重叠 | 同上 | 500 → 2,110 |
| 实际用量选择显式免费分支 | 同上 | 20,000 → 0 |

| 原异步图片入口的缓存明细 | `/async/v1/images/generations` | 500 → 2,110 |
| `quality=high` 冻结后保留固定价条件 | 同上 | 20,000 → 20,000 |
| 上游 502 后任务失败，全额退款 | `/async/v1/generateImage` | 12,500 → 0 |

8 个任务的最终实扣合计 **49,570**。钱包与受限令牌均为剩余 **9,950,430**、used_quota **49,570**；渠道 used_quota 也为 **49,570**，提交请求数为 **8**。失败任务按现有合同保留原消费日志额度 12,500，并另记退款日志 12,500；消费日志总额 62,070 减退款日志 12,500，净额正好 49,570，不能直接把消费日志合计当净扣款。

缓存案例读取实际消费日志的 `expr_b64` 和 `billing_tokens`：`p=300, cr=200, img=300, img_cr=200, img_o=200, c=0`。解码表达式手算 `(300*2 + 200*0.5 + 300*5 + 200*0.1 + 200*10) / 1e6 * 500000 * 1 = 2110`，与两个异步入口的任务额度、日志及账目一致。

测试 fixture 初次设置阈值时假定估算为 1,000，实际服务 `PreConsumedQuota` 为 500，导致零价案例未发生预扣。核实持久化快照后，将 fixture 条件改为 `len>100`，最终证据明确记录预扣 20,000 后退至 0；没有调整预期扣费来绕过验证。
