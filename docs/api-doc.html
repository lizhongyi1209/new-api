接入 O1Key API

所有接口共用一套 Bearer 鉴权。先上传参考素材取得公网地址，再提交生成任务，最后按 task_id 轮询结果。

1
上传素材

本地文件先换取公网 URL，线上素材可直接使用。

2
提交任务

选择模型与参数，拿到 task_id。

3
轮询结果

查询至 SUCCESS 或 FAILED，再下载产物。

请求参数

字段必填类型说明
model是string使用上表中的完整模型名称。
prompt是string图片生成或编辑指令。
images否array参考图数组。支持 URL、Data URI、原始 Base64、fileData 和 inlineData。第一张是编辑目标。
markup否object2.5+ 标注图编辑。传 {"image_url": "..."}，与 images 等宽等高、透明底，标注层不叠加在原图上。与 prompt 一起说明「改什么」和「保留什么」。
mask否object蒙版局部重绘。传 {"image_url": "..."}，需带 alpha 通道；与 markup 互斥。蒙版仅作用于第一张参考图。
n否integer生成图片数量，1–128，默认 1。
size否stringauto 或 WIDTHxHEIGHT；常用尺寸见下表。
quality否string通用：low、medium、high、auto；2.5 / 2.6 额外支持 xhigh、max。
complexity否string仅 2.6：low、medium、high（默认 high）。控制渲染前的规划强度，越高越慢、改动幅度越大。
background否stringauto、transparent 或 opaque。透明背景要求 PNG 或 WebP。
output_format否stringpng（默认）、jpeg、webp；仅 2.6 额外支持 svg、gif。
output_compression否integer0–100，仅对 jpeg / webp 生效。SVG 与 GIF 不支持。
partial_images否integer0–3，渐进预览帧数，每帧额外计费。SVG 与 GIF 不支持。
frame_count否integer仅 GIF：2–64 帧，默认 9。
frame_duration_ms否integer仅 GIF：每帧 20–2000 毫秒，默认 200，按 10ms 取整。
input_fidelity否string2.5 / 2.6 可传。GPT Image 2 必须省略，该系列始终高保真处理输入图。
moderation否stringauto 或 low。

请求参数

images否string[]公网图片 URL 数组，最多 10 张。单张参考图也必须放入数组；图层拆分模式必须且只能传 1 张。

图层拆分

规则说明
输入images 必须且只能包含 1 张待拆分图片。
输出data.images 返回 1 张底图和最多 16 个图层，按 z_index 表示图层顺序。
图层信息每项可包含 bounding_box、name 和 description；bounding_box.absolute 为绝对像素坐标，bounding_box.normalized 为 0–1000 归一化坐标。
失败处理任一图层生成失败时，整个任务返回 FAILURE，不返回部分结果。
数量上限提示词要求的图层数量超过上限时，超出部分可能不会返回。

预扣与结算：提交时按高清档预扣，任务完成后按实际档位结算，差额自动退回。余额不足高清档时请求会被直接拒绝。最终价格乘以调用密钥所属分组的倍率。

创建素材

POST/v1/seedance/assets

通过公开 URL 创建可复用素材。仅使用一次的素材可直接在视频请求中传入 URL。

字段必填类型说明
type是stringdreamina、doubao 或 hc（兼容旧名）；须与视频模型对应
url是string公开素材地址；HC 要求 HTTPS，Dreamina 与 Doubao 接受 HTTP(S)。asset:// 和 data: 会被拒绝
name否string素材名称
asset_type否stringimage、video 或 audio；默认 image
model否string用于选择渠道，并在 Dreamina / Doubao 上转发给上游。Dreamina 可省略；如填写，使用本站公开名（推荐简写如 dreamina-seedance-2-0-mini，兼容 -hc 旧名）或上游 dreamina-*-max。Doubao 建议省略；如填写，使用 doubao-seedance-2-0 或 doubao-seedance-2-0-260128-max

type: "dreamina" 转发到 POST /v2/sd-max/assets，type: "doubao" 转发到 POST /v2/db-sd-max/assets。这两条上游路径也可以直接调用，请求体字段为 URL、AssetType、Name、Model，响应原样返回 Id、Ref、Status。上传是 POST 到不带 id 的路径。

国外 Dreamina 预上传流程

  1. POST /v1/seedance/assets：type 为 dreamina，model 为即将用于生成的简写（示例用 dreamina-seedance-2-0-mini），asset_type 为 image，url 为公网图片。
  2. GET /v1/seedance/assets/{data.Id}?type=dreamina：每 1–2 秒查询，直到 data.Status 为 Active。记下 data.Ref（形如 asset://...）。
  3. POST /v1/video/generations：model 仍用同一个简写，把 Ref 填进 content[].image_url.url，role 为 reference_image。示例为 resolution: "480p"、duration: 4、generate_audio: false。
  4. GET /v1/video/generations/{id}：使用创建响应里的本站 task_...，直到 status 为 completed 或 failed。句柄已是 Active 时，任务通常直接是 queued，而不是素材准备中的 in_progress。

右侧示例里的素材 ID、任务 ID 和图片地址都是占位示例，不是线上记录。只使用一次的素材不必预上传，直接把公网 URL 放进视频请求即可。上传素材免费，句柄有效期 7 天。

句柄只对创建它时实际选中的那把上游密钥及其组织有效。Dreamina 与豆包不能混用。同一家族若有多把密钥或多个组织，只传 type 会在当前分组里选优先级最高的匹配渠道；之后生成若落到另一把密钥，句柄不能用。预上传请带上与生成请求相同的公开模型名，使两边都在提供该模型的渠道中选择。即便如此，同一模型仍可能对应多把密钥，句柄不能假定在同家族或同模型的其他密钥上可用。

Kling 3.0 Omni 视频生成

POST/kling/omni-video/kling-3.0-omni

使用官方 contents、settings、options 结构。无需传 model。

请求参数

字段类型必填说明
contentsarray是提示词、图片和视频输入集合。
contents[].typestring是prompt、first_frame、last_frame、refer_image、feature_video、base_video。
contents[].textstring条件type=prompt 时必填。官方上限 3072 字符，建议不超过 2500 字符。
contents[].urlstring条件图片支持公开 URL 或 Base64；视频使用可公开访问的 URL。
contents[].idstring否任务内唯一的引用 ID，可在提示词中以 @id 引用。
settingsobject条件输出设置。没有首帧或参考视频时必须提供，并填写 aspect_ratio。
settings.multi_shotboolean否是否生成多镜头，默认 true。
settings.audiostring否native 生成原生音频；original 保留参考视频声音；off 无音频。默认 off。
settings.resolutionstring否720p、1080p、4k，默认 720p。
settings.aspect_ratiostring条件16:9、9:16、1:1。没有首帧或参考视频时必填。

options.callback_urlstring否任务状态变化时接收通知的回调地址。
options.external_task_idstring否调用方自定义且账号内唯一的任务 ID。

素材与组合规则

  • 图片支持 JPG、JPEG、PNG，单文件不超过 50MB；宽高均不低于 300px，宽高比在 1:2.5 至 2.5:1 之间。
  • 首尾帧仅支持“仅首帧”或“首帧 + 尾帧”，不支持只传尾帧。
  • 视频支持 MP4、MOV，单文件不超过 200MB，时长 3-15.5 秒；最多传入 1 个参考视频。
  • feature_video 用作特征参考：multi_shot 必须为 true，audio 使用 off。
  • base_video 用作视频编辑：不能同时传首尾帧，multi_shot 必须为 false，audio 可用 original 或 off。
  • 多镜头提示词写法为“镜头序号, 秒数, 描述;”，支持 1-6 个镜头；各镜头时长之和必须等于 settings.duration。

Kling 3.0 动作模仿

POST/kling/motion-control/kling-3.0

请求体沿用 Kling 3.0 Motion Control 官方结构。每个任务提供 1 张角色外观参考图和 1 个动作参考视频；模型已由路径确定。

请求参数

字段类型必填说明
contentsarray是由提示词、角色图片和动作视频组成。
contents[].typestring是本页展示 prompt、image、video。
contents[].textstring条件type=prompt 时必填，最多 2500 字符；提示词本身可省略。
contents[].urlstring条件图片支持公开 URL 或 Base64；动作视频使用公开 URL。
settings.character_orientationstring是video：朝向跟随动作视频；image：朝向跟随参考图。
settings.audiostring否original 保留动作视频原声；off 无音频。默认 original。
settings.resolutionstring否720p、1080p，默认 720p。
options.callback_urlstring否任务状态变化时接收通知的回调地址。
options.external_task_idstring否调用方自定义且账号内唯一的任务 ID。
options.watermark_info.enabledboolean否是否同时生成带水印结果，默认 false。

素材规则

  • 必须且只能传 1 个 image 和 1 个 video。
  • 图片支持 JPG、JPEG、PNG，最大 50MB；宽高均不低于 300px，宽高比在 1:2.5 至 2.5:1 之间。
  • 动作视频支持 MP4、MOV，最大 100MB，宽高均在 340-3850px 之间；建议使用人物完整可见、无遮挡、无切镜、无明显运镜的连续单镜头。
  • character_orientation=video 时动作视频可为 3-30 秒；设为 image 时可为 3-10 秒。
  • video 更适合复杂动作；image 保持参考图朝向，并更适合通过提示词控制镜头运动。
